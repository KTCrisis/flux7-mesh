# A new or changed upstream declaration is held until an operator accepts it

- **Problem**: with hot reload, a `command:` line added to the config file was executed within a second, and a server seen for the first time was trusted on first use. The restart it replaced was a human act; nothing had taken its place. The file is writable by anything that can write files as the mesh's user, and an agent whose policy allows a file-writing tool is such a thing: it could make the mesh run a program, which is leaving the mesh's governance. Raised in review before the release.
- **Decision**: a declaration that appears or changes while the mesh runs starts nothing. It is held (`upstreams.Propose`), the declaration it would replace keeps running, and `POST /mcp-servers/{name}/accept` (`mesh7 upstream accept <name>`, the console) starts it. `GET /mcp-servers/held` shows what each would run: command and arguments or URL, names of env and header keys, never their values; admin only. Removing a declaration is applied at once. What was accepted is remembered in the state database, one fingerprint per server name (`upstream_accepted`), and a start launches only the declarations that match: a service is started again by a reboot or a crash with nobody watching, so a start is no more of a go-ahead than a file change. The first start ever trusts the file once and records it; a marker row keeps an emptied list from looking like a first start. The fingerprint covers transport, command, arguments, URL, env names and values and header names; header values are left out, tokens rotate. A file change that holds or removes something is recorded as `mesh.upstream_file_change`, an accept as `mesh.upstream_accept`.
- **Why**: the mesh cannot assume its files are protected elsewhere, and it already refuses to make a new or changed tool callable without an accept (pinning); a program it would execute deserves at least that. What is kept from hot reload: no restart, no cut for the other upstreams, removals at once.
- **Limits**: a declaration that differs from the accepted one is held at start with nothing running in its place, since the accepted declaration itself is not stored (it would mean keeping env values on disk). Without `storage_path` nothing is remembered and every start trusts the file. The state database is as writable as the config: keep it out of reach too. Without `auth.admin_token` any local process can call the control plane, `accept` included; the hold stops an agent confined to mesh tools, not one with a shell. Policy files are still applied on change: an agent that can write `policy_dir` can widen its own rights. Keep the config and `policy_dir` out of reach of what agents can write.
- **Where**: `cmd/mesh7/upstreams.go` (`Propose`, `Held`, `Accept`, `StartDeclared`), `cmd/mesh7/accepted.go`, `storage/sqlite.go` (schema v5), `cmd/mesh7/mesh.go`, `proxy/upstreams.go`, `internal/opcli/upstream.go`; tests `TestUpstreamsProposeHoldsNewAndChangedDeclarations`, `TestUpstreamsProposeWithdrawnOrRevertedIsNoLongerHeld`, `TestUpstreamsProposeRemovesAtOnce`, `TestRestartStartsOnlyAcceptedDeclarations`, `TestRestartAfterEverythingWasRemovedIsNotAFirstUse`, `TestDeclFingerprint`.
