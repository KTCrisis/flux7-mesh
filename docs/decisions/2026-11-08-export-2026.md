# mesh7 serves MCP 2026-07-28 clients

- **Problem**: a client pinned to 2026-07-28 could not use mesh7's export (no `server/discover`, `Mcp-Session-Id` required). And a request whose `Mcp-Name` header named one tool while its body called another was not refused, although a gateway in front may filter on that header.
- **Decision**: the same Server serves both eras (`mcp/era_server.go`). A request with the version in `params._meta` is modern: no initialize, no session, identity from its own credential, `server/discover` answered, `resultType` on results, `ping` gone, an unknown version gets -32022. Over HTTP, headers that disagree with the body get -32020 in either era. `initialize` still answers 2024-11-05, so existing clients negotiate exactly as before.
- **Why**: one dispatch keeps stdio and HTTP aligned; refusing a header mismatch closes the false-label path for header-routing gateways.
- **Where**: `mcp/era_server.go`, `mcp/server.go` (HandleRequestWith), `mcp/http_server.go`; tests in `mcp/era_server_test.go`; checked with the official SDK v2 client in legacy, auto and pinned modes. Grouping without sessions: the trace context (Traceparent header, or `traceparent` in `_meta`) and the client's `X-Session-Id` label, which fills the session of a modern request so traces group by it and a session halt reaches it. The label is declared, not proven: an agent halt remains the real stop.
