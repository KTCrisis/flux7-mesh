# The admin token guards writes, so an agent on the host cannot settle its own approvals

- **Problem**: with no admin token the control plane only checked for loopback. An agent with a shell on the mesh7 host could approve its own held call with one POST (the approval message names the route), and `approved_by` records what the caller declares. Found in use on 2026-11-14, not by audit.
- **Decision**: `auth.admin_scope: all | writes` (default `all`, unchanged) and `auth.admin_token_file`. With `writes`, every POST, PUT or DELETE of the control plane needs the token and GET stays open to loopback. A missing or empty token file stops the daemon, and `mesh7 validate` reports it before a restart. The operator CLI sends the token from `MESH_ADMIN_TOKEN` or the file `MESH_ADMIN_TOKEN_FILE` names, never from a file it finds on its own (it would fetch the token for an agent that runs it). sup7 reads it from `mesh.token_file`.
- **Why**: the agent being governed must not be able to settle its own approval. Writes only, because local watchers (mesh7-pane, deck7) must keep reading decisions without holding the token. Stated limits: agents under the same Unix user can still read a token file they are not kept from, and a relay that holds the token (the console today, with no login) re-opens the door.
- **Where**: `config/config.go`, `adminAuth` in `cmd/mesh7/mesh.go`, `adminAuthorized`/`isRead` in `proxy/handler.go`, `adminToken` in `internal/opcli/halt.go`, `cmd/mesh7/validate.go`; tests in `proxy/handler_test.go`, `cmd/mesh7/admin_auth_test.go`, `internal/opcli/token_test.go`, `cmd/mesh7/validate_test.go`.
